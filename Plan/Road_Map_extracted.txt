1. MỤC TIÊU HỆ THỐNG
Xây dựng một nền tảng thương mại điện tử xuất khẩu quốc tế và bán lẻ xuyên biên giới có tính chất ERP thu nhỏ (Mini-ERP for Cross-Border Trade), tích hợp B2C Retail Commerce, B2B Wholesale/Export RFQ Engine, Container/CBM Packing Optimization, Multi-Currency/i18n, International Payment (Stripe 3D Secure / T/T Wire Transfer), Export Document Management (Commercial Invoice, Packing List, Bill of Lading) và Audit/Security. Hệ thống phải đảm bảo data integrity, transaction safety, idempotency và khả năng mở rộng multi-market/multi-warehouse.
Tên gọi
Phạm vi & Công nghệ lựa chọn
Core Backend
ASP.NET Core 9.0 Web API + Entity Framework Core (hoặc Node.js/NestJS Clean Architecture)

Frontend Web
React 19 / Next.js (App Router, Server Components tối ưu SEO quốc tế) + Tailwind CSS + Shadcn UI

Modular Monolith phân lớp rõ ràng; Docker containers; GitHub Actions CI/CD; Jira Software tracking
2. NGUYÊN TẮC KIẾN TRÚC
[ ] React/Next.js chỉ là presentation và client state; tuyệt đối không là nguồn sự thật cho business rule.
[ ] ASP.NET Core Web API là business authority duy nhất.
[ ] Pricing tiers, MOQ validation, Incoterms calculations, Payment intents, và Authorization phải được quyết định ở backend.
[ ] SQL Server là Single Source of Truth cho toàn bộ dữ liệu nghiệp vụ.
[ ] Mọi biến động tồn kho xuất nhập khẩu phải đi qua Inventory Transaction / Ledger (Không sửa trực tiếp Inventory.Quantity).
[ ] Báo giá B2B (RFQ) tuân thủ quy trình State Machine bất biến: Draft -> Submitted -> Quoted -> Accepted -> Deposit Paid -> In Production -> Shipped -> Completed.
[ ] Transaction lịch sử là immutable; sửa sai bằng reversal/credit note/adjustment có lưu vết Audit Log.
[ ] Business logic không nằm trong Controller; Controller chỉ làm nhiệm vụ parse request và dispatch use-case.
[ ] DTO / API Contract tách biệt hoàn toàn khỏi Entity Database để bảo mật.
[ ] Concurrency & Idempotency phải được thiết kế ngay từ đầu (xử lý trùng lặp thanh toán Stripe Webhook & giữ chỗ hàng tồn container).
[ ] Audit Log toàn bộ các hành động nhạy cảm: sửa giá sỉ, đổi cước vận tải, duyệt thanh toán T/T, phát hành chứng từ.
[ ] Multi-currency và Multi-warehouse phải được thiết kế ngay từ schema cơ sở dữ liệu.
3. KIẾN TRÚC TỔNG THỂ
Hệ thống hoạt động theo luồng chuẩn enterprise: Client React/Next.js -> HTTPS REST API (JWT/API Key) -> Application Services (Use Cases) -> Domain Entities & Business Rules -> Infrastructure Layer -> SQL Server. SignalR chạy song song cho realtime notifications. Background Service đồng bộ tỷ giá ngoại tệ và quét hạn thanh toán chứng từ.
Client Layer: React / Next.js (B2C Storefront + B2B Portal + Admin ERP)
      ↓ (HTTPS / REST API / WSS SignalR)
API Gateway / Middleware (Auth, CORS, Rate Limiting, CorrelationId, Exception)
      ↓
Application Layer (Use Cases / DTOs / CQRS / Validators)
   ├── Auth & Company Verification Service
   ├── Catalog & Dynamic Tiered Pricing Engine
   ├── B2C Order & Stripe Payment Engine
   ├── B2B RFQ Negotiation & Incoterms Pricing Engine
   ├── Logistics, CBM & Container Loading Optimization Engine
   ├── Export Document Generation (PDF Proforma/Commercial/Packing)
   ├── Inventory Ledger & Multi-Warehouse Allocation
   ├── Notification & SignalR Hubs
   └── Currency Exchange Rate Service (Background Job)
      ↓
Domain Layer (Entities, Value Objects, Domain Exceptions, Business Invariants)
      ↓
Infrastructure Layer (EF Core, SQL Server, AWS S3 Storage, Stripe SDK, QuestPDF)
